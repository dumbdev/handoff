# Handoff

**Freelance escrow that can't be ghosted.**

Plain escrow doesn't fix the freelancer's real problem. The money sits in the contract, but releasing it still needs the client to click a button. When the client goes quiet after delivery, the freelancer is stuck: the funds exist, they just never move.

Handoff puts a clock on the review. The client escrows the fee and picks two deadlines, both counted in **Bitcoin blocks**:

- **Deliver by** — if the freelancer delivers nothing by then, the client takes a refund.
- **Review window** — once work is delivered, the client has this long to approve. If they say nothing, the freelancer takes the payment themselves.

Either way the money lands somewhere. Nobody can stall it into limbo.

- **Built with:** [Scaffold Stacks](https://scaffoldstacks.mintlify.app/) (`stacksdapp` CLI, Clarity 6, Next.js)

## How it works

| Who | Action | Contract function |
|---|---|---|
| Client | Escrow the fee, set both deadlines | `create-job (freelancer, amount, deliver-in, review-window, brief)` |
| Freelancer | Say the work is done, starting the review window | `mark-delivered (job-id)` |
| Client | Approve and pay, at any time | `release (job-id)` |
| Freelancer | Take payment after the review window closes | `claim (job-id)` |
| Client | Take a refund if nothing was delivered by the deadline | `refund (job-id)` |
| Freelancer | Hand the job back before delivering | `decline (job-id)` |
| Anyone | Read a job, or list a person's jobs | `get-job`, `get-user-jobs` |

Rules the contract enforces:

- **Delivery closes the refund door.** Once work is marked delivered, the client can only approve or let the window run out. They cannot yank the money back.
- **The review window only starts at delivery**, so a freelancer who delivers early isn't punished for it.
- **A happy client never waits.** `release` works the moment they're satisfied, before or after delivery.
- **No admin.** The deployer has no special powers. Every payout goes to the job's own client or freelancer.
- **Each job is isolated.** Settling one job can't touch another job's escrow.

Time is measured with `burn-block-height`, the Bitcoin chain Stacks settles on. On mainnet that's about 10 minutes a block, so a one-week review window is roughly 1,000 blocks.

## Run it

Requires Rust, Node 20+, and Clarinet 3.23+ (`stacksdapp doctor` checks everything).

```bash
cargo install stacksdapp          # on Ubuntu first: sudo apt install pkg-config libssl-dev
stacksdapp test                   # 25 contract tests + 8 frontend tests
stacksdapp dev --network testnet  # app on http://localhost:3000
```

To deploy your own copy, put a funded testnet seed phrase in `contracts/settings/Testnet.toml` (never commit it; the pre-commit hook blocks it) and run `stacksdapp deploy --network testnet --yes`.

Layout:

```
contracts/contracts/handoff.clar      the contract
contracts/tests/handoff.test.ts       simnet tests
frontend/src/components/handoff/      job list, job card, new-job form
frontend/src/lib/handoff.ts           parsing and formatting helpers
frontend/src/lib/__tests__/           tests for the read-only parsing layer
frontend/src/generated/               hooks generated by `stacksdapp generate`
frontend/src/app/debug/               generated debug panel for every function
```

## Tests

**Contract (25 tests):** funding and escrow accounting, every input validation, the full happy path, claiming before and after the review window, refunds before and after the deadline, declines, double-settlement attempts, calls from the wrong party, and isolation between concurrent jobs.

**Frontend (8 tests):** the parsing layer, driven by real `cvToValue` output. These caught a live bug — Clarity optionals come back nested one level deeper than expected, so `delivered-at` parsed as `NaN` and the countdown would have rendered blank in the demo.

## Status

Testnet demo, not audited. Holds STX only. Real disputes would need an arbitrator; this version deliberately has none, so no third party can freeze a payment.
